# S10 — The Ratio R and the Numerator/Denominator Window

**Campaign:** Erdős #699, Cycle 1, strategy round.
**Agent:** S10. **Status:** strategy paper. This route does **not** prove
#699. It gives an exact, prime-by-prime reformulation of the
counterexample condition in terms of two short windows of consecutive
integers, a complete characterisation of "bad" primes in the upper band
`(j/2, j]`, an exact formula in the lower band `[i, j/2]`, a clean
sub-regime (regime R1 below) in which the whole problem collapses to
the upper band, and explicit near-miss examples showing that the
window conditions *can* all hold simultaneously — so the route's
breaking point is located exactly, not vaguely.

**Problem.** For all `1 ≤ i < j ≤ n/2`, some prime `p ≥ i` divides both
`C(n,i)` and `C(n,j)`. Equivalently, with `V_i(n)` the part of `C(n,i)`
supported on primes `≥ i`, `gcd(V_i(n), C(n,j)) > 1` always.
**Established inputs used** (from `erdos-699/PHASE0.md`, `RESULTS.md`):
the reduction "counterexample (with `(n,i)` not one of the 12 EEES78
exception pairs) `⇒ C(n,i) < C(2j, 2(j−i))`", i.e. `n ≤ N(i,j)`; the
closure of `j ≤ 3i/2`; the sweep finding no counterexample with
`n ≤ 10000`; Sylvester–Schur (some prime `p > i` divides `C(n,i)`).

**Notation used throughout.** `d := j − i ≥ 1`,

```
S(n,i)   := { p prime : p ≥ i,  v_p(C(n,i)) ≥ 1 }        (nonempty, by Sylvester–Schur),
e_p      := v_p(C(n,i)),
DEN      := (i, j]      = {i+1, …, j},          |DEN| = d,
NUM      := (n−j, n−i]  = {n−j+1, …, n−i},      |NUM| = d,
A_p      := v_p( Π NUM ) = v_p((n−i)!) − v_p((n−j)!),
B_p      := v_p( Π DEN ) = v_p(j!) − v_p(i!),
Δ_p      := B_p − A_p.
```

A prime `p ∈ S(n,i)` is called **bad** (for the triple `(n,i,j)`) if
`p ∤ C(n,j)`, and **good** otherwise. A triple is a counterexample iff
every `p ∈ S(n,i)` is bad.

---

## 1. Idea

Passing from `C(n,i)` to `C(n,j)` multiplies by a single explicit
rational number `R` whose numerator and denominator are each a product
of `d = j−i` consecutive integers (Lemma 1). The exponent of a prime
`p` can therefore only move by `Δ_p = B_p − A_p`, the difference of
the `p`-adic contents of two windows of length `d`: a *fixed* window
`DEN = (i, j]` depending only on `(i,j)`, and a *sliding* window
`NUM = (n−j, n−i]` whose position is `n`. A prime `p ≥ i` dividing
`C(n,i)` is destroyed on the way to `C(n,j)` iff the denominator
window beats the numerator window by at least its whole exponent in
`C(n,i)`: `Δ_p ≥ e_p`. The game is then completely concrete. Primes
`p > j` can never be destroyed, because `DEN` contains no multiple of
`p` at all (Lemma 2), so every bad prime lies in `[i, j]`. For
`p ∈ (j/2, j]` the denominator window contains `p` exactly once, to
the first power, so `B_p ≤ 1` and badness collapses to two elementary
conditions: `e_p = 1` and `NUM` contains no multiple of `p`, the
latter being an explicit set of residue classes for `n mod p`
(Theorem 3). For `p ∈ [i, j/2]` higher prime powers enter, but
`Δ_p` has an exact term-by-term formula (Lemma W, Theorem 5) and is
capped by `⌊log_p j⌋`, so any `p ∈ S(n,i)` with a large exponent is
automatically good. The dividing line `j = 2i` organises everything:
if `3i/2 < j < 2i` the lower band is empty and the *entire*
counterexample condition is the upper-band system of residue
conditions (regime R1, §5); if `j > 2i` the lower band opens up, but
the upper band acquires a sub-interval of automatically good primes.
The breaking point (§6) is sharp: the residue system of R1 is
simultaneously satisfiable — at `(n,i,j) = (119,39,59)`, which lies
*inside* the reduction interval (`N(39,59) = 119`), all five primes of
`S(n,i) ∩ [i,j]` are bad at once, and at `(4871,59,113)` eleven are —
and in every such example the triple is rescued exclusively by primes
`p > j`, which Lemma 2 makes automatically good and which are
abundant for large `n`. So the window route alone cannot finish; what
it does is isolate the exact statement a finishing argument must
prove (§5, Tasks T1–T3), and it settles some families outright
(§7: `n` prime; any `n` whose largest prime factor window is short).

## 2. The ratio R and the window valuations

### Lemma 1 (the R formula)

For `1 ≤ i < j ≤ n/2`, with `d = j − i`,

```
C(n,j) = C(n,i) · R,      R = Π NUM / Π DEN
     = [ (n−i)(n−i−1)···(n−j+1) ] / [ (i+1)(i+2)···j ].
```

Moreover `R ∈ ℚ_{>0}` and for every prime `p`,

```
v_p(C(n,j)) = e_p + A_p − B_p = e_p − Δ_p.        (∗)
```

**Proof.** `C(n,j)/C(n,i) = [n!/(j!(n−j)!)] · [i!(n−i)!/n!]
= [(n−i)!/(n−j)!] / [j!/i!]`. The numerator `(n−i)!/(n−j)!` is the
product of the `d` integers `n−j+1, …, n−i`, i.e. `Π NUM`; the
denominator `j!/i!` is the product of the `d` integers `i+1, …, j`,
i.e. `Π DEN`. Taking `v_p` of both sides of `C(n,j) = C(n,i)·R` gives
`(∗)`, since `v_p(Π NUM) = A_p` and `v_p(Π DEN) = B_p` by definition
(the `v_p` of a factorial quotient is the `v_p` of the corresponding
window product). ∎

**Verification.** The formula was checked in exact integer arithmetic
(`C(n,j)·ΠDEN = C(n,i)·ΠNUM`) for **all** `1 ≤ i < j ≤ n/2`, `n < 80`
(Python stdlib, `math.comb`, `math.prod`); no failure. Note `R` is
rational, not integral in general (e.g. `(n,i,j) = (10,2,4)`:
`R = (8·7)/(3·4) = 14/3`, and indeed `C(10,4)/C(10,2) = 210/45 = 14/3`).

**Corollary (badness criterion).** For `p ∈ S(n,i)`, `p` is bad iff
`Δ_p ≥ e_p`; then `v_p(C(n,j)) = e_p − Δ_p = 0`. (Since
`v_p(C(n,j)) ≥ 0` always, badness is the equality case of `(∗)`.)

### Lemma 2 (primes above j are automatically good)

If `p > j` and `p ∈ S(n,i)`, then `p` is good; in fact
`v_p(C(n,j)) ≥ e_p ≥ 1`. Consequently **every bad prime lies in
`[i, j]`**.

**Proof.** Every element of `DEN = (i, j]` is `≤ j < p`, so no element
is divisible by `p` and `B_p = 0`. By `(∗)`,
`v_p(C(n,j)) = e_p + A_p ≥ e_p ≥ 1`, as `A_p ≥ 0`. ∎

This re-derives, by a two-line window argument, the same localisation
the reduction obtains from `v | C(j, j−i)` (whose prime factors `≥ i`
lie in `[i, j]`); §7 compares the two caps in detail.

### Lemma W (window counts, term by term) — the master formula for Δ_p

For an integer `m ≥ 2` and any `a ≥ 0`, the number of multiples of `m`
in a window `(a, a+d]` is `⌊(a+d)/m⌋ − ⌊a/m⌋ = ⌊((a mod m) + d)/m⌋`.
Writing `d = q_k m + t_k` with `m = p^k`, `0 ≤ t_k < m`:

```
count of multiples of p^k in (a, a+d]  =  q_k + 1{ a mod p^k ≥ p^k − t_k }   if t_k > 0,
                                       =  q_k                                if t_k = 0.
```

Both windows are windows of this shape: `DEN = (i, i+d]` and
`NUM = (n−j, (n−j)+d]`. Hence, by Legendre's formula applied to the
two factorial quotients,

```
Δ_p = Σ_{k≥1} ( ⌊j/p^k⌋ − ⌊i/p^k⌋ − ⌊(n−i)/p^k⌋ + ⌊(n−j)/p^k⌋ )
    = Σ_{k≥1} ( 1{ i mod p^k ∈ C_k } − 1{ (n−j) mod p^k ∈ C_k } ),     (†)
```

where `C_k := [p^k − t_k, p^k − 1]` if `t_k := d mod p^k` is nonzero,
and the `k`-th summand is `0` if `t_k = 0`. In particular **each
summand of `(†)` lies in `{−1, 0, +1}`**, and the `k`-th summand is
`+1` iff the denominator window crosses a multiple of `p^k` that the
numerator window does not cross.

**Proof.** Legendre: `A_p = Σ_k (⌊(n−i)/p^k⌋ − ⌊(n−j)/p^k⌋)` and
`B_p = Σ_k (⌊j/p^k⌋ − ⌊i/p^k⌋)`; subtract. The bracket
`⌊(a+d)/m⌋ − ⌊a/m⌋` depends only on `a mod m` and `d`: writing
`a = sm + r`, it equals `⌊(r+d)/m⌋ = q_k + ⌊(r + t_k)/m⌋`, and
`⌊(r+t_k)/m⌋` is `1` iff `r ≥ m − t_k` (when `t_k > 0`), else `0`.
Applying this with `a = i` and `a = n−j` and subtracting gives `(†)`;
the shared `q_k` cancels, which is the point: **the two windows have
the same length, so `Δ_p` sees only the two residue positions, not
the sizes of the windows**. ∎

**Corollary (digit-sum form).** By Legendre's digit-sum formula
`v_p(m!) = (m − s_p(m))/(p−1)`, the factors of `d` cancel and

```
Δ_p = ( s_p(i) − s_p(j) + s_p(n−i) − s_p(n−j) ) / (p − 1),
```

where `s_p` is the sum of base-`p` digits. Similarly
`e_p = ( s_p(i) + s_p(n−i) − s_p(n) ) / (p−1)` (the Kummer carry
count, up to the factor `p−1`). Badness `Δ_p ≥ e_p` is thus a single
inequality between base-`p` digit sums of five explicit integers.

**Corollary (universal cap).** `Δ_p ≤ #{ k ≥ 1 : p^k ≤ j } =
⌊log_p j⌋`. Hence if `e_p > ⌊log_p j⌋` then `p` is automatically good.

**Proof of cap.** In `(†)`, a summand can be `+1` only if `DEN`
contains a multiple of `p^k`; a positive multiple of `p^k` in
`(i, j]` is `≥ p^k` and `≤ j`, forcing `p^k ≤ j`. All other summands
are `≤ 0`. ∎

## 3. The upper band `p ∈ (j/2, j]`: exact badness conditions

### Theorem 3

Let `p ∈ (j/2, j]`, `p ≥ i`, `p ∈ S(n,i)`.

**(a) The denominator window.** If `p > i`, then `B_p = 1` exactly.
If `p = i` (so `i` is prime and `i > j/2`), then `B_i = 0`.

**(b) Badness.** If `p > i`: `p` is bad **iff** `e_p = 1` **and**
`A_p = 0`. If `p = i`: `p` can never be bad; a counterexample must
have `e_i = 0`, i.e. `i ∉ S(n,i)`.

**(c) The residue condition.** `A_p = 0` iff `NUM` contains no
multiple of `p`, iff either of the following equivalent conditions
holds (both sides are empty conditions, i.e. `A_p ≥ 1` forced, when
`d ≥ p`):

```
(n−i) mod p   ∈ { d, d+1, …, p−1 },          (U-form)
(n−j+1) mod p ∈ { 1, 2, …, p−d }.            (L-form)
```

In particular exactly `p − d` of the `p` residue classes for
`n mod p` (when `d < p`) make `A_p = 0`.

**Proof.** (a) Let `p > i`. An element of `DEN` divisible by `p` is a
multiple `mp ≤ j < 2p` (as `p > j/2`), so `m = 1`: the only such
element is `p` itself, which lies in `DEN` since `i < p ≤ j`, and
`v_p(p) = 1`. Hence `B_p = 1`. If `p = i`: `DEN = (i, j]` excludes
`i` itself, and the next multiple `2i > j` (as `i > j/2`), so no
element of `DEN` is divisible by `i` and `B_i = 0`.

(b) Badness is `Δ_p ≥ e_p` (§2 Corollary). For `p > i`,
`Δ_p = 1 − A_p ≤ 1` and `e_p ≥ 1`, so `Δ_p ≥ e_p` forces
`A_p = 0` and `e_p = 1` (and then `Δ_p = 1 = e_p`, `v_p(C(n,j)) = 0`).
For `p = i`, `Δ_i = −A_i ≤ 0 < 1 ≤ e_i`: never bad.

(c) `A_p = 0` iff no element of `NUM = (n−j, n−i]` is divisible by
`p` (any such element contributes `≥ 1` to `A_p`; prime powers are
irrelevant since `A_p = 0` iff there is no multiple of `p` at all).
Put `U := n−i`, `r := U mod p`. The largest multiple of `p` that is
`≤ U` is `U − r`; it is positive (indeed `≥ p`), because
`U ≥ n−j+1 ≥ j+1 > p` using `n ≥ 2j`. It lies in `NUM` iff
`U − r ≥ U − d + 1`, i.e. iff `r ≤ d − 1`; any other multiple of `p`
in `NUM` would be a larger one `≤ U`, and there is none. Hence `NUM`
avoids multiples of `p` iff `r ≥ d`: the U-form. With
`L := n−j+1 = U−d+1`, `s := L mod p`: the first multiple of `p` that
is `≥ L` is at distance `(p − s) mod p` from `L`; it lies in `NUM`
iff that distance is `≤ d−1`. Avoidance iff `s = 0` is excluded
(distance `0`) and `p − s ≥ d`, i.e. `s ∈ {1, …, p−d}`: the L-form.
The two forms are equivalent via `r = (s + d − 1) mod p` (no
wrap-around occurs in the avoidance range). If `d ≥ p`, the U-form
set `{d, …, p−1}` is empty and indeed every `d` consecutive integers
contain a multiple of `p`, so `A_p ≥ 1`. ∎

**Remark (the joint first-order condition).** For `p > i` one also
has, at the level of multiples of `p` itself, `e_p ≥ 1` iff the
window `(n−i, n]` crosses a multiple of `p` (since `v_p(i!) = 0`),
i.e. iff `(n−i) mod p ≥ p − i` up to higher-power corrections. In
regime R1 (`d < i`, see §5) `p − i ≤ d`, so the badness conditions
"`e_p = 1`, `A_p = 0`" are, to first order in `p`, the *single*
condition `(n−i) mod p ∈ {d, …, p−1}` (a set of `p − d` classes):
such a residue puts the crossing multiple in `(n−i, n]` within the
first `p − (n−i mod p) ≤ p − d ≤ i` steps but keeps it out of `NUM`.
The only higher-order correction is that the unique multiple of `p`
in `(n−i, n]` might be divisible by `p^2`, raising `e_p` to `≥ 2`
and rescuing `p`. This is why simultaneous badness, while
restrictive, is a positive-density CRT event in `n` — see §6.

## 4. The lower band `p ∈ [i, j/2]`: exact conditions

Here `2p ≤ j`, so `DEN` can contain both `p` and `2p`, and prime
powers `p^k ≤ j` genuinely contribute. There is no collapse to
`e_p = 1`; the exact statement is the master formula.

### Theorem 5

Let `p ∈ [i, j/2]`, `p ∈ S(n,i)`. Then `p` is bad iff

```
Σ_{k≥1} ( 1{ i mod p^k ∈ C_k } − 1{ (n−j) mod p^k ∈ C_k } )  ≥  e_p,
```

with `C_k` as in `(†)`. In particular:

**(i) Cap.** Badness requires `e_p ≤ ⌊log_p j⌋`.

**(ii) Sub-band `p ∈ (√j, j/2]`.** Here `p > √j` gives `p^2 > j`,
so `⌊log_p j⌋ = 1` and the cap forces
`e_p = 1` *and* `Δ_p = 1`; `Δ_p = 1` requires the `k = 1` summand of
`(†)` to be `+1` (i.e. `i mod p ∈ C_1` and `(n−j) mod p ∉ C_1`) and
the total of the `k ≥ 2` summands to be `≥ 0` (they are each
`≤ 0` here only in the sense that their `DEN`-indicator vanishes:
for `k ≥ 2`, `p^k > j`, so the `k`-th summand is
`−1{ (n−j) mod p^k ∈ C_k } ≤ 0`; badness iff the `k = 1` summand is
`+1` and every `k ≥ 2` summand is `0`).

**(iii) Sub-band `p ≤ √j`.** `e_p` may be as large as
`⌊log_p j⌋ ≥ 2`, and badness is a genuine multi-scale condition:
for each `k` with `p^k ≤ j`, the denominator window's crossing of a
multiple of `p^k` must not be cancelled by a numerator crossing, and
the total surplus must reach `e_p`.

**Proof.** The displayed condition is `(†)` combined with the badness
criterion `Δ_p ≥ e_p`. (i) is the universal cap. (ii): if `p^2 > j`,
for `k ≥ 2` the `DEN` side of `(†)` has indicator `0` (no multiple of
`p^k` in `DEN`, by the cap argument), so those summands are `≤ 0`,
while the `k = 1` summand is `≤ 1`; `Δ_p ≥ e_p ≥ 1` then forces the
stated equalities. (iii) is a restatement of `(†)`. ∎

Note the lower band is *empty* iff `i > j/2`, i.e. iff `j < 2i`. That
is the organising fact of §5.

## 5. Synthesis: the strongest exact partial statement

### Theorem S10 (window characterisation of counterexamples)

For every `1 ≤ i < j ≤ n/2`, the triple `(n,i,j)` is a
counterexample to #699 **if and only if** every `p ∈ S(n,i)`
satisfies `Δ_p ≥ e_p` (with `Δ_p` given by `(†)`), and this system
implies all of the following:

1. **Localisation.** Every `p ∈ S(n,i)` with `p > j` is good
   (Lemma 2), i.e. no bad prime lies outside `[i, j]`. A
   counterexample requires every member of `S(n,i)` to be bad;
   hence a counterexample satisfies `S(n,i) ⊆ [i, j]` itself. (This
   is a very strong necessary condition: `C(n,i)` may have **no**
   prime factor `≥ i` exceeding `j`.)

2. **Upper band.** Every `p ∈ S(n,i) ∩ (j/2, j]` with `p > i`
   satisfies `e_p = 1`, `A_p = 0`, and the residue conditions of
   Theorem 3(c). If `i` is prime, `i > j/2` and `i ∈ S(n,i)`, the
   triple is **not** a counterexample (Theorem 3(b)).

3. **Automatic goodness in R3's upper sub-band.** If `j > 2i` and
   `p ∈ S(n,i) ∩ (j/2, d]` (nonempty range since `d = j−i > j/2`),
   then `A_p ≥ 1` (a window of length `d ≥ p` meets a multiple of
   `p`) while `B_p ≤ 1`, so `v_p(C(n,j)) ≥ e_p ≥ 1`: `p` is good and
   the triple is not a counterexample. Hence a counterexample with
   `j > 2i` has `S(n,i) ∩ (j/2, d] = ∅`.

4. **Lower band.** Every `p ∈ S(n,i) ∩ [i, j/2]` satisfies the
   multi-scale condition of Theorem 5, and `e_p ≤ ⌊log_p j⌋`.

5. **Forced-prime exclusion.** If the interval
   `(max(j, n−i), n]` contains any prime `q`, then `q ∈ S(n,i)` with
   `e_q = 1`: `q` divides the window `(n−i, n]`, while `q > i` gives
   `q ∤ i!` and `q > n−i` gives `q ∤ (n−i)!`. And `q > j`, so `q` is
   good by Lemma 2 and the triple is **not** a counterexample. Hence
   a counterexample requires the interval `(max(j, n−i), n]` to be
   **prime-free**.

Quantifiers, stated once and exactly: the "only if" direction holds
for **all** `(n,i,j)` with `1 ≤ i < j ≤ n/2`, with **no** EEES78 or
reduction hypothesis; the "if" direction is the definition of a
counterexample unwound through `(∗)`.

### The regime table (dividing lines `j = 3i/2`, `j = 2i`, `j = 2i` vs `d = p`)

Write the open region `j > 3i/2` as `d > i/2`. The window analysis
splits it at `j = 2i` (i.e. `d = i`, i.e. `i = j/2`):

* **R1: `3i/2 < j < 2i`** (`i/2 < d < i`). The lower band `[i, j/2]`
  is **empty** (since `i > j/2`). Every bad candidate is in the upper
  band, and every prime of `S(n,i) ∩ [i,j]` exceeds `d` (as
  `p ≥ i > d`), so Theorem 3 applies with `p − d ≥ 1` live residue
  classes. **In R1, `(n,i,j)` is a counterexample iff
  `S(n,i) ⊆ [i,j]` and every `p ∈ S(n,i)` has `e_p = 1` and
  `(n−i) mod p ∈ {d, …, p−1}`** (plus `e_i = 0` if `i` is prime, in
  which case `i ∉ S(n,i)` anyway and the condition is vacuous for
  `p = i`). This is a complete, elementary reformulation of the
  conjecture in R1 — no EEES78, no size estimate.

* **R2: `j = 2i`** (`d = i`). The lower band is the singleton `{i}`.
  Primes `p ∈ S(n,i)`, `p > i`, are exactly as in R1 (`p > i = d`).
  The prime `i` itself, if prime and in `S(n,i)`, is governed by
  Theorem 5 with cap `⌊log_i 2i⌋` (which is `1` for `i > 2`):
  badness would need `Δ_i ≥ e_i` with `Δ_i` at most that cap.

* **R3: `j > 2i`** (`d > i`). Both bands are present. The upper band
  splits at `p = d`: primes `≤ d` are automatically good if they lie
  in `S(n,i)` (item 3 above), primes `> d` behave as in R1, and the
  lower band `[i, j/2]` carries the multi-scale conditions of
  Theorem 5 with caps `e_p ≤ ⌊log_p j⌋` that weaken as `p` shrinks
  (for `p = i` small relative to `j`, `⌊log_p j⌋` can be `≥ 3`, and
  this band is where the window method is weakest).

**Where the method is strong and where it is not, honestly.** In R1
the method is a *complete* reformulation with all conditions at the
level of single prime moduli: the whole content of the conjecture in
R1 is the system in Theorem S10, items 1, 2 and 5. In R3 the lower
band is the obstacle: for small `p` the cap `⌊log_p j⌋` is not
binding against typical `e_p`, and `(†)` couples the position of
`n` modulo `p^k` for several `k` at once. And in **all** regimes the
window conditions on primes in `[i, j]` are, by §6, simultaneously
satisfiable; the condition that actually fails in every near-miss is
item 1 / item 5, the demand that `C(n,i)` have *no* good prime
factor above `j`. The window route therefore does not finish the
problem by itself. It converts the remaining work into three precise
tasks (§8).

## 6. Breaking point: simultaneous badness really happens

The conditions of Theorem 3 are not vacuous, not mutually
incompatible, and not rare. All computations below are Python stdlib
only; the search that produced Example A runs in under a second, the
verification of Example B in well under a second (script in the
Appendix).

### Example A (inside the reduction interval, at its very endpoint)

`(n, i, j) = (119, 39, 59)`: regime R1 (`3i/2 = 58.5 < 59 < 78 = 2i`),
`d = 20`, `NUM = (60, 80] = {61,…,80}`, `DEN = (39, 59]`.
`N(39, 59) = 119`, so this `n` is the **largest** value the
reduction (for non-exception `(n,i)`; `(119,39)` is not an EEES78
exception pair) does not already exclude.

The primes in `[i, j] = [39, 59]` are exactly `41, 43, 47, 53, 59`,
and **all five divide `C(119, 39)`, each to the first power, and all
five are bad**:

| p  | e_p | B_p | A_p | (n−i) mod p | required range [d, p−1] | (n−j+1) mod p | allowed [1, p−d] |
|----|-----|-----|-----|-------------|--------------------------|---------------|-------------------|
| 41 | 1   | 1   | 0   | 39          | [20, 40]                 | 20            | [1, 21]           |
| 43 | 1   | 1   | 0   | 37          | [20, 42]                 | 18            | [1, 23]           |
| 47 | 1   | 1   | 0   | 33          | [20, 46]                 | 14            | [1, 27]           |
| 53 | 1   | 1   | 0   | 27          | [20, 52]                 | 8             | [1, 33]           |
| 59 | 1   | 1   | 0   | 21          | [20, 58]                 | 2             | [1, 39]           |

So `v_p(C(119,59)) = 0` for every prime `p ∈ S(119,39) ∩ [39,59]`.
The triple is **not** a counterexample for exactly one reason:
`S(119,39)` also contains the eight primes
`83, 89, 97, 101, 103, 107, 109, 113`, all `> j`, hence all good by
Lemma 2 (each in fact divides `C(119,59)` to the first power). The
window conditions on the in-range primes are met *perfectly and
simultaneously*; only the out-of-range primes rescue the conjecture,
and the window method has nothing to say against them beyond
Lemma 2's automatic goodness.

This example is not isolated: the Appendix search over R1 pairs with
`i < 40`, restricted to `n ∈ [2j, N(i,j)]`, found **377 triples** in
which every prime of `S(n,i) ∩ [i,j]` (at least three of them) is
simultaneously bad, the maximum simultaneous count inside the
reduction interval being 5 (Example A, and also e.g.
`(122, 39, 61)` with bad primes `43, 47, 53, 59, 61`).

### Example B (eleven simultaneous bad primes, outside the interval)

`(n, i, j) = (4871, 59, 113)`: regime R1 (`88.5 < 113 < 118`),
`d = 54`, `NUM = (4758, 4812]`, `DEN = (59, 113]`. The primes in
`[59, 113]` are `59, 61, 67, 71, 73, 79, 83, 89, 97, 101, 103, 107,
109, 113`. Of these, `59, 89, 109` do not divide `C(4871, 59)`
(`e_p = 0`; note `e_59 = 0` is exactly what Theorem 3(b) requires of
the prime `p = i`), and the remaining **eleven**
`61, 67, 71, 73, 79, 83, 97, 101, 103, 107, 113` all divide
`C(4871, 59)` to the first power and are **all bad**: for each,
`B_p = 1`, `A_p = 0`, and `(n−i) mod p ∈ [54, p−1]` (values: `54, 55,
55, 67, 72, 81, 59, 65, 74, 104, 66` respectively; the case `p = 61`
sits exactly on the boundary `(n−i) mod 61 = 54 = d`, and `p = 83`
has `(n−j+1) mod 83 = 28`, one inside the allowed maximum `p−d = 29`).
Again the rescue comes solely from above `j`: `S(4871,59)` has 49
primes, the other 38 all `> 113`, all good by Lemma 2.
Here `n = 4871 > N(59,113) = 337`, so the *reduction* excludes this
triple as a counterexample candidate on size grounds alone; the
example's role is to show that the window conditions themselves,
even imposed on eleven primes at once, have solutions in abundance —
they cannot yield a contradiction without an input that controls
the primes above `j`.

**Conclusion of §6.** The breaking point is exactly identified. The
window system (Theorems 3 and 5) is a *necessary* condition that is
far from sufficient: its in-range part is simultaneously satisfiable
inside and outside the reduction interval. Any completion of this
route must supply an argument that, under the in-range badness
system, `C(n,i)` nevertheless acquires a prime factor `> j` in
`S(n,i)` (equivalently, that `S(n,i) ⊆ [i,j]` is impossible) — or a
prime-gap input making the interval of item 5 nonempty.

## 7. Composition with the reduction

The established reduction says: for `(n,i)` not an EEES78 exception
pair, a counterexample satisfies `v = V_i(n) | C(j, d)` and
`C(n,i) < C(2j, 2d)`, i.e. `n ≤ N(i,j)`. How does the window route
interact with it?

**(a) The two localisations agree, and each caps exponents its own
way.** The key lemma gives `e_p ≤ v_p(C(j,d))` for every
`p ∈ S(n,i)` in a counterexample. The window gives `e_p ≤ Δ_p`.
In the upper band with `d < p ≤ j` and `p > i`:
`v_p(C(j,d)) = v_p(j!) − v_p(i!) − v_p(d!) = 1 − 0 − 0 = 1`,
the same cap `e_p = 1` that Theorem 3(b) forces — consistent, no
gain either way. Where `d ≥ p` (R3 upper sub-band, item 3 of
Theorem S10) the window is **strictly stronger**: it shows such a
`p` is automatically good, while `v_p(C(j,d))` can be `≥ 1` and the
key lemma alone does not exclude `p`. In the lower band the two caps
are incomparable in general: `v_p(C(j,d)) = B_p − v_p(d!)` versus
`Δ_p = B_p − A_p`; a counterexample must satisfy both, i.e.
`e_p ≤ min(Δ_p, B_p − v_p(d!))`, a genuinely combined necessary
condition worth recording for the verifier agents.

**(b) Does the window route shrink `N(i,j)`? Honestly: not
unconditionally, and Example A shows why it cannot shrink it via
in-range primes alone.** For fixed `(i,j)` in R1, the window
conditions are conditions on `n mod p` for `p ∈ S(n,i)` — but
`S(n,i)` itself varies with `n`, and Example A is a triple at
`n = N(39,59)` meeting *all* in-range conditions. So no argument
that looks only at primes in `[i,j]` can lower `N(39,59)` below
`119`. Any shrinking must use the primes above `j`, i.e. must be a
statement about `V_i(n)` as a whole — which is what the reduction's
size argument already is.

**(c) What the window route does shrink: the set of admissible `n`
for fixed `(i,j)`, along explicit families.** Theorem S10 item 5
excludes every `n` for which `(max(j, n−i), n]` contains a prime,
for **all** `(i,j)` at once and with no EEES78 hypothesis. Clean
corollaries:

* **`n` prime:** for every `1 ≤ i < j ≤ n/2`, `p = n` divides both
  `C(n,i)` and `C(n,j)` (as `0 < i < j < n`), and `p = n ≥ i`. So
  #699 holds for all prime `n`, elementarily. (Item 5 with
  `q = n > max(j, n−i)`.)
* **`n` with a short prime gap below it:** if the largest prime
  `q ≤ n` satisfies `q > max(j, n−i)` — equivalently the prime gap
  below `n` is `< n − max(j, n−i)` — then `(n,i,j)` is not a
  counterexample. Inside the reduction interval `n ≤ N(i,j)`, these
  `n` can be deleted from the checklist without any gcd computation.
  This is a per-`n` shrink of the checklist, not a lowering of the
  maximum `N(i,j)`: the endpoint `n = N(i,j)` itself may survive it
  (Example A: `(max(59, 80), 119] = (80, 119]` contains primes, and
  indeed item 5 is exactly what rescues Example A — consistently).

**(d) As a filter, not a proof.** Combined with the sweep machinery,
the window conditions give a cheap necessary-condition filter for
candidate triples in the open region: check, for each
`p ∈ S(n,i) ∩ [i,j]`, the residue/exponent conditions of
Theorems 3 and 5 before computing any gcd. §6 shows the filter's
in-range part passes 377 triples with `i < 40` inside their
reduction intervals, so the filter does **not** materially reduce
the sweep's work; its value is structural, not computational.

## 8. What a finishing argument must do (tasks for prover agents)

* **T1 (R1 is the cleanest target).** Prove: for `3i/2 < j < 2i` and
  `2j ≤ n ≤ N(i,j)`, `(n,i)` not an EEES78 exception, it is
  impossible that simultaneously (i) every `p ∈ S(n,i)` lies in
  `[i,j]` with `e_p = 1` and `(n−i) mod p ∈ [d, p−1]`, and
  (ii) `S(n,i) ⊆ [i,j]`. By Theorem S10/R1 this would close R1.
  Suggested lever: (i) forces `V_i(n) = Π_{p ∈ S(n,i)} p` to be a
  squarefree product of primes in `[i,j]` each `≡`-constrained
  mod `p`; combine with `V_i(n) | C(j,d)` **and**
  `V_i(n) > C(n,i)^{1/2}` (EEES78) to get
  `C(n,i)^{1/2} < C(j,d)` with `C(n,i)`'s large-prime part
  squarefree and supported in a short interval — a size/support
  tension the plain reduction does not use.

* **T2 (prime gaps).** Prove the interval `(max(j, n−i), n]` in
  item 5 is nonempty for an explicit sub-regime (e.g. `i` large
  relative to `n^{0.525}` via known prime-gap bounds, or
  elementarily when `n − i` lies in a Bertrand-friendly range),
  closing that sub-regime outright.

* **T3 (R3 lower band).** Find a usable lower bound for some
  `e_p`, `p ∈ [i, j/2]`, exceeding `⌊log_p j⌋`, or a multi-scale
  incompatibility in `(†)`: the indicators for `k` and `k+1` are
  not independent (residues mod `p^{k+1}` determine residues mod
  `p^k`), and no agent has yet exploited this nesting.

**Known limits of this route, stated plainly.** (1) In-range window
conditions are simultaneously satisfiable (§6) — no contradiction
lives inside `[i, j]` alone. (2) The route's only handle on primes
`> j` is Lemma 2 plus the forced-prime item 5; controlling
`S(n,i) ⊆ [i,j]` in general is essentially the EEES78-type input the
reduction already uses. (3) In R3's lower band the conditions are
exact but not yet rigid enough to contradict typical exponent
patterns.

## Appendix: computational verification (Python stdlib only)

The following script (run during this strategy round, well under
one minute in total) verifies the R formula on all small cases,
verifies Examples A and B prime by prime against Theorems 3 and
S10, and confirms `N(39,59) = 119`, `N(59,113) = 337`.

```python
import math

def vpf(N, p):
    t = 0
    while N:
        N //= p; t += N
    return t

def vp_binom(n, k, p):
    return vpf(n, p) - vpf(k, p) - vpf(n - k, p)

def primes_between(a, b):
    return [x for x in range(max(a, 2), b + 1)
            if all(x % q for q in range(2, int(x**0.5) + 1))]

# (1) R formula: C(n,j) * prod(DEN) == C(n,i) * prod(NUM), all n < 80
for n in range(2, 80):
    for i in range(1, n // 2 + 1):
        for j in range(i + 1, n // 2 + 1):
            num = math.prod(range(n - j + 1, n - i + 1))
            den = math.prod(range(i + 1, j + 1))
            assert math.comb(n, j) * den == math.comb(n, i) * num

# (2) Example check: every prime of S(n,i) in [i,j] bad, rest good
def check(n, i, j, expected_bad):
    S = [p for p in primes_between(i, n) if vp_binom(n, i, p) > 0]
    bad = [p for p in S if vp_binom(n, j, p) == 0]
    assert bad == expected_bad, (n, i, j, bad)
    for p in bad:  # Theorem 3 data
        assert vp_binom(n, i, p) == 1
        assert vpf(n - i, p) - vpf(n - j, p) == 0      # A_p = 0
        assert vpf(j, p) - vpf(i, p) == 1              # B_p = 1
        assert (n - i) % p >= j - i                    # U-form residue
    return S

SA = check(119, 39, 59, [41, 43, 47, 53, 59])
assert [p for p in SA if p > 59] == [83, 89, 97, 101, 103, 107, 109, 113]
SB = check(4871, 59, 113, [61, 67, 71, 73, 79, 83, 97, 101, 103, 107, 113])
assert len(SB) == 49

# (3) N(i,j) values by the reduction's definition
def N_of(i, j):
    target = math.comb(2 * j, 2 * (j - i)); n = 2 * j
    while math.comb(n, i) < target:
        n += 1
    return n - 1

assert N_of(39, 59) == 119 and N_of(59, 113) == 337
print("all S10 checks passed")
```

The search behind Example A enumerated R1 pairs `i < 40`,
`n ∈ [2j, N(i,j)]`, testing for each prime `p ∈ [i,j]` with
`e_p ≥ 1` the badness inequality `B_p − A_p ≥ e_p` (Legendre
exponents as above); it found 377 triples where every such prime is
bad, with maximum simultaneous bad count 5. Example B was produced
by the analogous search in R1 with `n ≤ 5000` (first hit with 11
simultaneous bad primes at `(4871, 59, 113)`; a smaller 10-prime
example is `(2186, 59, 109)`, bad primes
`61, 67, 71, 79, 83, 89, 97, 103, 107, 109`).
